# 绘图模型选择与开放状态

2026-11-02，Souhub 工作台输入区增加“模型”菜单。用户可查看 GPT Image 2、GPT Image 2.5 Flare、GPT Image 2.5 Sunburst 的开放状态，只有已开放且当前主站密钥有权限的模型才能选择。当前生产只开放 `gpt-image-2`；两个 2.5 候选显示“暂未开放”。

生成与编辑请求传递所选模型，参考图和遮罩沿用原接口；每轮“参数与详情”保留提交时的模型。刷新保留有效的选择，历史模型关闭后重试会明确拒绝，不自动替换为其他模型。旧作品未保存模型时按原有 Image 2 展示。

## 模型清单的含义

账号仍从绘图站管理后台上传和管理。Sub2 管理绘图分组、用户密钥和账单，通过内部 Images 渠道调用绘图站引擎；用户请求不改用 Sub2 的另一套 OAuth 账号池。

Codex `/models` 返回的是驱动模型清单，`input_modalities: image` 表示可以输入图片，不代表图片生成能力。Sub2 的同步逻辑会为 OAuth 账号补充本地支持的图片候选，因此管理页面名单多于上游原始清单。绘图引擎的候选名单同样不能当作某个账号的实测授权证明。

绘图站用 `backend/image_models.py` 管理实现与开放状态。用户会话、公开 `/v1/models`、Gemini 模型列表取开放清单与主站密钥模型权限的交集。原生 Images 请求、异步任务和协议适配器执行同一开放校验。管理员看到 2.5 候选时，也不能绕过引擎的开放校验。

## 2.5 实测与调用边界

导入的 Codex Free 账号可以读取模型清单，但本次验证没有成功生成 2.5 图片：

- 直调 `/backend-api/codex/images/generations`，分别请求 Flare、Sunburst：均返回 HTTP 403，响应为 `Forbidden`。
- Responses 路径分别使用清单中的 `gpt-6-luna` 和 Sub2 当前驱动 `gpt-5.6-luna`，显式指定 Flare 图片工具：均返回 HTTP 400，提示图片工具不被接受。

这些结果不足以断言所有 Free 账号或所有路径都不可用，也不足以开放给用户。读取候选模型、显示本地额度或完成 OAuth 登录均不能代替一次真实图片结果验证。

2.5 的 Images 适配器使用绘图站 Codex 池、账号对应代理和完整模型名，支持生成、参考图编辑及单个原始遮罩；不添加套餐排除条件。HTTP 拒绝和连接中断不自动重放，也不改用其他模型。结果必须返回可验证的 PNG，才保存图片并记录本地成功额度。保留上游明确报告的用量，不套用 Image 2 的 token 估算。旧 `codex-gpt-image-2` 路径保持独立。

内部通用 Conversation 路径拒绝 2.5，防止把图片候选送进网页 Image 2 流程。公开 Chat/Responses/Gemini 图片适配器则转换为带原模型的 Images 任务，保持主站计费及任务幂等。

## 开放条件与报价

`MI_ENABLED_IMAGE_MODELS` 默认为 `gpt-image-2`，只接受实现清单中的完整模型名。未来开放 2.5 前须依次确认：目标绘图账号真实返回对应图片；生成、编辑、参考图、遮罩及失败行为符合预期；主站渠道、分组、单独售价和实际账单已经验收。仅改环境变量或模型白名单不构成完整开放。

报价请求带所选 `model`，缓存按密钥与模型隔离；返回报价的模型必须完全匹配。当前主站报价接口仍提供 Image 2 报价，若未来选用 2.5 而主站未提供对应报价，页面显示“价格暂不可用”，不会显示 Image 2 的价格。本次没有修改主站售价、分组或账单规则。
