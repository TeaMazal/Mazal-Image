# 多站迁移与升级

## 新站

每站使用一个新的空源码目录和独立 Compose 项目名；允许同一台服务器上运行。将干净源码包解压到新目录，重新执行 init_site.py，分别设置新站的名称、主站和绘图域名、网关与未占用端口。

禁止将老站目录连同 `state/` 或 `.env` 直接复制给新站。不要共用账号数据库、内部密钥、备份卷或可信 origin。是否为新站导入相同账号由站主自行决定，不包含在程序迁移中。

新站主站渠道要使用新站生成的内部密钥和引擎地址；新站用户使用新主站签发的 API 密钥。新的域名和 origin 不会自动修改旧站配置。

## 用户作品

浏览器按 origin 存储图库和偏好，图库身份还与密钥派生标识有关。换域名或换密钥不会自动看到旧作品。用户先在旧站导出不含密钥的作品 ZIP，再使用对应身份在新站导入；不要将某个用户的图库变成公共示例数据。

## 同站升级

1. 保存当前源码版本、镜像 ID 和小份配置备份，核对磁盘空间；不要备份整个媒体目录。
2. 在独立空目录用模拟配置完成新包测试，查看 CHANGELOG。
3. 在维护时间将新源码更新到原站目录，保留原 `.env`、`state/`、`backups/`；不要再次执行初始化。
4. 若有字段变化，按变更说明调整 `.env`，执行 `docker compose up -d --build`。
5. 检查健康、普通用户权限、管理员入口、主站计费路由和新品牌/域名，必要时恢复原镜像与配置。

引擎数据库结构变化前应单独做一致性数据库备份并验证恢复。跨不兼容引擎版本不能仅替换镜像后假定可以回滚。

`docker compose down` 不删除本项目 bind mount 数据；不要运行带清理数据目录的第三方脚本。归档或删除站点应由站主在确认备份后自行处理。
