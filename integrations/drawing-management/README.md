# Souhub 绘图管理 r28

主站左侧独立绘图管理，账号、分组、代理、用户密钥和账单继续属于 Sub2 主站；绘图服务只保留用户工作台、作品、模板、画布和存储服务。2026-11-07 已部署到 Souhub，新加坡 Mazal 未部署。

八个页面：概览、绘图账号、代理池、生图测试、模板管理、图片与存储、绘图设置、任务与诊断。

## 主站代码

`backend.patch` 是实际部署的 r27 → r28 增量，`backend-manifest.json` 包含精确的前后文件哈希。先应用 `../sub2-web-accounts` 的 r27 集成并核对完整主站版本，再运行：

```sh
python apply_backend.py --backend /path/to/sub2api/backend
python apply_backend.py --backend /path/to/sub2api/backend --apply
```

哈希不同必须先人工合并，不能强制覆盖。新文件包含管理接口、Web/Codex 授权解析与 OAuth、模型目录、代理订阅/核心/健康维护、管理测试任务与设置。原有图片 Base64 规范化修复保留补位符，解决部分参考图编辑被本地拒绝的问题。

前端四个 `drawing-*` 文件挂入主站现有 Vue 路由和 AppLayout，使用主站现有认证 HTTP 客户端。它们是部署版源码，不能直接替换其他版本的 Vue 编译产物：本次主站资源命名空间为 `assets-souhub-drawing-r28`，入口注入和 sidebar 改动位于服务器操作目录的 `package_frontend_remote.py`。用户绘图站前端未替换。

## 数据与执行

- 导入是本地授权文件/令牌导入，不再同步 CPA 或其他 Sub2 的账号池。支持预览、同来源邮箱去重、更新授权保留分组/出口/启停。新账号默认暂停。
- Web 与 Codex 分开执行，模型目录、执行器支持和真实成功记录分别展示。用户目前仍仅开放 `gpt-image-2`，不能将目录里的 2.5/2.6 当作成功验证。
- 代理节点复用主站表；订阅、健康维护和核心配置使用主站 settings。新核心只管理新导入转换节点，旧核心与现有节点没有迁移覆盖。自动健康维护默认关闭；手动停用优先。
- 账号固定出口不允许隐式直连。主站原有代理到期/备用出口策略仍在原代理管理页面；新页面当前不新增“随机轮换出口”或请求失败后自动换号重发。
- 管理测试按账号诊断，消耗上游额度，不扣普通用户余额。普通用户计费走原主站网关。管理任务及图片持久化于主站 `/app/data/drawing-tests`，逐张保存、幂等提交、重启后标记未确认而不重发。
- 主站执行设置真正传入 Web worker，影响生图、额度与模型读取。旧绘图服务里的账号池与本地用户密钥不恢复。

## 存储、备份和边界

绘图管理桥仅允许模板、图片、存储、备份、日志和保留设置；旧账号池及生图入口不能通过桥调用。配置密码不回显，留空保留。图片默认保护；手动解除保护后，服务器任务仍引用的图片仍不能删除。浏览器本地历史无法由服务器完整枚举，解除保护时需管理员核对。

后端和独立 maintenance 容器同时升级保护逻辑。模板和保护记录纳入绘图文件备份。主站账号、代理订阅、管理测试记录与账单另随主站数据库及 app-data 备份；恢复由运维核对版本后执行，未提供浏览器一键覆盖生产数据的按钮。

OAuth 链接、PKCE/state、同账号重新授权和失败保存重试已实现并通过接口检查；完整的人类浏览器登录尚未验收。现有授权文件导入与真实 Web 生图/编辑已验证。

发布与验收详见 `../../docs/DRAWING_MANAGEMENT_20261107.md`。`verification.json` 是脱敏后的线上核对结果，不包含令牌、数据库或私钥。
